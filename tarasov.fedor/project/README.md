# Gadget Hub

Интернет-магазин надежных гаджетов. Учебный проект по дисциплине
«Web-разработка»: клиентская часть на React, серверная часть на NestJS,
база данных PostgreSQL 16 и ORM Drizzle.

Сейчас завершены **этапы 1–6**: настроено рабочее пространство,
перенесены ассеты из учебных материалов, описана схема базы данных,
созданы миграции, наполнен русскоязычный каталог из 32 товаров,
реализован REST API для авторизации, товаров и заказов, добавлены
общий макет, авторизация, главная страница с каруселями, каталог с
фильтрами и карточкой товара, а также корзина, оформление заказа и
история покупок. Интерфейс приведен к макету `Gadget Hub.fig` и
`Gadget Hub - pages.pdf`.

## Быстрый старт

Требования: Node.js 20+, npm 10+, Docker Desktop.

```bash
# 1. Установить зависимости всего рабочего пространства
npm install

# 2. Подготовить переменные окружения
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env

# 3. Запустить PostgreSQL 16
docker compose up -d db

# 4. Применить миграции и заполнить базу
npm run db:migrate
npm run db:seed

# 5. Запустить сервер и клиент одновременно
npm run dev
```

После запуска откройте http://localhost:3000.

## Демонстрационный доступ

| Поле | Значение |
|---|---|
| Логин | `admin` |
| Пароль | `123456` |

Пароль хранится в базе данных в виде bcrypt-хэша, а не в открытом виде.

## Клиентские маршруты

| Маршрут | Доступ | Назначение |
|---|---|---|
| `/` | публичный | Главная страница |
| `/login` | публичный | Вход в систему |
| `/catalog` | только авторизованным | Каталог товаров |
| `/cart` | только авторизованным | Корзина |

Неавторизованный посетитель при переходе в `/catalog` или `/cart`
перенаправляется на `/login`. Неизвестные адреса возвращают на главную.

Авторизация хранится в HTTP-only cookie, а клиент дополнительно кэширует
данные пользователя для быстрого восстановления интерфейса и проверяет
сессию через `GET /me`. Корзина хранится в `localStorage` под ключом
`gadget-hub-cart:v1` и синхронизируется между вкладками.

## Главная страница

- Баннер «Супер распродажа» с роботом из Figma-макета.
- Две закольцованные карусели: «Хиты продаж» и «Новинки», по три
  карточки с фотографией, названием, ценой в рублях и рейтингом.
- Переключение стрелками с переходом от последнего товара к первому и
  обратно.
- Клик по товару ведет на `/login` без авторизации и на
  `/catalog?product=<id>` с открытием модального окна после входа.
- Блок «Преимущества» с иконками, вырезанными из учебного макета.
- Контактный блок «Работаем 24/7» над общим подвалом.
- Состояния загрузки, ошибки и пустой подборки на русском языке.

## Каталог и карточка товара

- Сортировка чипами «Новые», «Популярные», «Подешевле»,
  «Подороже».
- Двухползунковый фильтр цены, синхронизированный с полями «От» и «До».
- Фильтры по цене, типу товара и цвету; пустой набор чекбоксов означает
  «все варианты».
- Применение фильтров по кнопке «Показать» и полный сброс кнопкой
  «Сбросить».
- Три карточки в ряд, пагинация по 9 товаров и формат
  `1, 2, 3, ..., последняя` при большом числе страниц.
- Карточки показывают фото, название, цену в рублях, рейтинг и метки.
- Кнопка «В корзину» превращается в степпер `− [количество] +`;
  изменения сохраняются в `localStorage` и отражаются в шапке.
- Модальное окно с фото, описанием, характеристиками, рейтингом, ценой
  и управлением корзиной; закрывается по `Esc` и кнопке `X`.

## Корзина и заказы

- Вкладки «Корзина» и «История заказов».
- Пустая корзина показывает требуемый текст со ссылкой на каталог.
- Строки корзины содержат чекбокс, фото, название, количество, сумму и
  кнопку удаления.
- Удаление одного товара и выбранных товаров подтверждается модальным
  окном с кнопками «Да» и «Отмена».
- Форма оформления: почта, телефон, способ получения, адрес только для
  доставки, оплата, упаковка.
- Обязательные поля подсвечиваются красным и показывают русские
  сообщения.
- После успешного заказа корзина и `localStorage` очищаются, открывается
  модальное окно «Спасибо, ваш заказ успешно оформлен».
- История заказов загружается из `GET /orders` и показывает номер, дату,
  количество товаров и сумму в рублях.

## Схема базы данных

### `users`

| Поле | Тип | Особенности |
|---|---|---|
| `id` | serial | первичный ключ |
| `username` | varchar(64) | уникальный логин |
| `password_hash` | varchar(255) | bcrypt-хэш |
| `created_at` | timestamp with time zone | дата создания |

### `goods`

| Поле | Тип | Особенности |
|---|---|---|
| `id` | serial | первичный ключ |
| `title` | varchar(255) | название товара |
| `description` | text | описание |
| `specs` | jsonb | русские пары «характеристика — значение» |
| `price` | integer | цена в рублях |
| `rating` | real | рейтинг от 1 до 5 |
| `image_url` | varchar(255) | путь к изображению |
| `category` | varchar(100) | категория |
| `color` | varchar(50) | цвет |
| `is_new` | boolean | метка «Новинка» |
| `is_bestseller` | boolean | метка «Хит» |
| `created_at` | timestamp with time zone | дата добавления |

### `orders`

| Поле | Тип | Особенности |
|---|---|---|
| `id` | serial | первичный ключ |
| `user_id` | integer | внешний ключ на `users.id` |
| `email` | varchar(255) | необязательное поле |
| `phone` | varchar(30) | обязательное поле |
| `delivery_method` | varchar(20) | `pickup` или `delivery` |
| `address` | varchar(500) | необязательное поле |
| `payment_method` | varchar(20) | `card` или `cash` |
| `needs_packaging` | boolean | по умолчанию `false` |
| `total_quantity` | integer | общее количество товаров |
| `total_price` | integer | итоговая стоимость в рублях |
| `created_at` | timestamp with time zone | дата оформления |

### `order_items`

| Поле | Тип | Особенности |
|---|---|---|
| `id` | serial | первичный ключ |
| `order_id` | integer | внешний ключ на `orders.id` |
| `good_id` | integer | внешний ключ на `goods.id` |
| `quantity` | integer | количество единиц |
| `price_at_purchase` | integer | цена на момент покупки |

Дополнительно в базе действуют ограничения: рейтинг находится в диапазоне
от 1 до 5, цены и количества неотрицательны, способы доставки и оплаты
принадлежат допустимым значениям.

## Наполнение каталога

Seed-скрипт создает:

- пользователя `admin` с паролем `123456`;
- 32 товара из предоставленного набора;
- русские названия, описания, характеристики, категории и цвета;
- цены в рублях и рейтинги от 4,1 до 5;
- разные комбинации меток «Новинка» и «Хит».

Изображения товаров лежат в `frontend/public/assets/goods/` и доступны по
пути `/assets/goods/image_N.png`. Скрипт можно запускать повторно: он
очищает таблицы и создает данные заново.

## REST API

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `POST` | `/login` | публичный | Вход по логину и паролю |
| `POST` | `/logout` | публичный | Завершение сессии |
| `GET` | `/me` | авторизованный | Текущий пользователь |
| `GET` | `/goods` | публичный | Полный список товаров |
| `GET` | `/orders` | авторизованный | История заказов пользователя |
| `POST` | `/orders` | авторизованный | Создание нового заказа |
| `GET` | `/health` | публичный | Проверка работоспособности |

Сессия хранится в HTTP-only cookie `gadget_hub_session` с JWT-токеном.
Клиент должен отправлять запросы с `credentials: "include"`.

`GET /goods` возвращает полный массив товаров, отсортированный по дате
добавления: сначала новые. Фильтрация, сортировка и пагинация выполняются
на клиенте.

### Создание заказа

```json
{
  "email": "user@example.ru",
  "phone": "+7 999 123-45-67",
  "deliveryMethod": "delivery",
  "address": "Санкт-Петербург, ул. Барочная, д. 7",
  "paymentMethod": "По карте",
  "needsPackaging": true,
  "items": [
    { "goodId": 13, "quantity": 2 },
    { "goodId": 25, "quantity": 1 }
  ]
}
```

Обязательные поля: `phone`, `deliveryMethod`, `paymentMethod`,
`needsPackaging` и непустой `items`. Поле `address` обязательно при
`deliveryMethod: "delivery"`. Допустимые способы оплаты: `"По карте"` и
`"Наличными"`. Сумма заказа рассчитывается на сервере по актуальным ценам.
